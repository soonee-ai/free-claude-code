# Wiring FCC to Hermes Agent

FCC's bundled `fcc-hermes` launcher needs Hermes >= 0.20.4 semver and a managed
overlay (see `src/free_claude_code/cli/launchers/hermes.py`). Git-source Hermes
builds report no semver (`git.50a6abc` style) and fail the compatibility gate.
This doc wires FCC manually — the overlay generated by the launcher is the
template, and the result is fully supported by Hermes' custom-provider schema
(`hermes_cli/runtime_provider_custom.py` parses `transport: codex_responses`,
`key_env`, and `extra_headers` natively).

## What FCC exposes

`fcc-server` (default port 8082) serves exactly:

- `POST /v1/responses` — OpenAI **Responses** format, **streaming only**
  (`stream:false` returns a structured error)
- `POST /v1/messages` (+ `/v1/messages/count_tokens`) — Anthropic Messages
- `GET /v1/models`, `GET /`, `GET /health`

There is **no `/v1/chat/completions`** — FCC is not a generic OpenAI drop-in.
Any client must speak Responses (Anthropic-native) or Messages (Anthropic) or
use the Claude-Code/agents harnesses FCC can launch.

## Security baseline (do this BEFORE first start)

FCC defaults to `HOST=0.0.0.0` (internet-exposed on a VPS!) and auth off. In
`~/.fcc/.env` (created on first start; write it first, mode 0600):

```dotenv
HOST=127.0.0.1
PROXY_AUTH_ENABLED=true
ANTHROPIC_AUTH_TOKEN=<43-char urlsafe token>   # NOT the default "freecc"
FCC_OPEN_BROWSER=false
```

Verify with `ss -tlnp | grep 8082` → must show `127.0.0.1` only; wrong token
must 401 on `/v1/responses`.

## Provider keys

Add upstreams in `~/.fcc/.env` (e.g. `NVIDIA_NIM_API_KEY=nvapi-…`) and restart
`fcc-server` (it is a plain process: `~/.local/bin/fcc-server > /tmp/fcc-server.log 2>&1`).
Check routing via `GET /` → `{"status":"ok","provider":"nvidia_nim","model":"…"}`.

## The Hermes-side provider block

In the target Hermes profile's `config.yaml` (set with
`hermes -p <profile> config set providers.fcc '{...}'`):

```yaml
providers:
  fcc:
    name: Free Claude Code
    api: http://127.0.0.1:8082/v1
    key_env: FCC_PROXY_TOKEN                    # any var name in the profile .env
    extra_headers:
      Authorization: "Bearer ${FCC_PROXY_TOKEN}"
    transport: codex_responses                  # THE key field
    default_model: claude-sonnet-4-20250514
    models:
      claude-sonnet-4-20250514: {}
    discover_models: false
```

Then put the proxy token into the profile `.env` as `FCC_PROXY_TOKEN=<same
43-char value as ANTHROPIC_AUTH_TOKEN in ~/.fcc/.env>`.

The Claude-tier wire slugs (`claude-fable-5`, `claude-opus-4-20250514`, …) are
cosmetic routing names FCC maps onto the selected model — they let
agent-model-tier routing (`MODEL_FABLE/OPUS/…`) keep working across any
upstream. They are not real Anthropic models.

## Validation sequence (all verified in practice)

1. Wrong bearer → 401; right bearer + unknown model → clean provider-chain
   error (JSON, not HTML).
2. `switch_model()` on the Hermes side resolves
   `provider=fcc, api_mode=codex_responses, base_url=http://127.0.0.1:8082/v1`,
   bearer resolved from `key_env`.
3. Real streaming probe: content non-empty, `response.completed`, usage
   (in/out) present.
4. Live agent: `API call: model=… provider=fcc` lines in the Hermes log with
   200s in the fcc-server access log.
